# STM32MP157 到 STM32F407 心跳通讯说明

## 模块目的

本模块说明 STM32MP157 通过串口探测 STM32F407 是否在线的最小协议。当前实现复用 F407 工程已有的 USART1 文本命令入口，不新增二进制帧、不改变传送带、电感检测、称重或机械臂控制逻辑。

## 通讯协议

| 项目 | 内容 |
|---|---|
| 通讯方向 | STM32MP157 -> STM32F407 查询；STM32F407 -> STM32MP157 回复。 |
| F407 串口 | USART1，PA9 为 TX，PA10 为 RX。 |
| MP157 设备节点 | 当前 Qt 健康检测默认使用 `/dev/ttySTM2`。 |
| 串口参数 | 115200，8 数据位，无校验，1 停止位，关闭硬件流控。 |
| 查询帧 | ASCII 文本 `STATUS\r\n`。 |
| F407 回复 | ASCII 文本 `[OK][F4] READY\r\n`。 |
| MP157 判定 | 回复中包含 `ACK`、`OK`、`F4` 或 `READY` 任一关键字即可认为 F4 接入；当前回复同时包含 `OK/F4/READY`。 |
| 硬件动作 | `STATUS` 只返回在线状态，不执行去皮、标定、电机、机械臂或 LDC 操作。 |
| 超时判断 | MP157 当前等待约 250 ms；无回复时显示 F4 待接入。 |

## 硬件资源

| 硬件资源 | 用途 | 接线要求 |
|---|---|---|
| F407 USART1_TX / PA9 | F407 向 MP157 回发 `[OK][F4] READY`。 | 连接到 MP157 对应串口 RX。 |
| F407 USART1_RX / PA10 | F407 接收 MP157 发来的 `STATUS\r\n`。 | 连接到 MP157 对应串口 TX。 |
| GND | 两块板串口电平参考地。 | STM32MP157 与 STM32F407 必须共地。 |

## 验证方式

| 测试目标 | 执行位置 | 命令 | 预期输出/现象 | 失败时排查 |
|---|---|---|---|---|
| 确认 MP157 串口节点存在 | STM32MP157 开发板 | `test -e /dev/ttySTM2 && echo ttySTM2-ok` | 输出 `ttySTM2-ok`。 | 若无输出，检查设备树串口节点、内核日志和串口是否被其它程序占用。 |
| 配置串口参数 | STM32MP157 开发板 | `stty -F /dev/ttySTM2 115200 raw -echo -crtscts` | 命令无报错。 | 若报错，检查 `/dev/ttySTM2` 权限、节点名称和驱动加载状态。 |
| 手动发送心跳 | STM32MP157 开发板 | `printf 'STATUS\r\n' > /dev/ttySTM2; timeout 1 cat /dev/ttySTM2 | head -c 80` | 输出包含 `[OK][F4] READY`。 | 若无回复，检查 TX/RX 是否交叉、两板是否共地、F407 是否烧录新固件、USART1 是否仍是 115200 8N1。 |
| 串口助手验证 F407 | Windows 串口助手 | 发送文本 `STATUS`，末尾追加 `\r\n`。 | 收到 `[OK][F4] READY`。 | 若未知命令，确认发送的是 ASCII 文本而不是十六进制字符串，且 F407 使用的是最新固件。 |
| Qt 健康状态验证 | STM32MP157 Qt 界面 | 启动 Qt 摄像头界面，等待健康检测刷新。 | F4 状态从“待接入”变为“接入”。 | 若仍待接入，先用上一条手动命令验证，再检查 Qt 默认串口是否仍为 `/dev/ttySTM2`。 |
